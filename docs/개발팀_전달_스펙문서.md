## 1. 제품 개요

**학쫑프로 로드맵**은 대한민국 고등학생의 **학생부종합전형(학종)** 준비를 돕는
**AI 기반 세특(세부능력 및 특기사항) 설계 도구**입니다.

컨설턴트가 학생의 **학생부(PDF)** 와 **목표 학과·학년·이수 과목**을 입력하면, AI가:

1. 학생의 탐구 이력을 분석해 **강점·심화 계보·공백 영역**을 진단(프로파일)하고,
2. 다음 학기에 어떤 방향으로 세특을 설계해야 하는지 **총론(설계 방향)** 을 제시하며,
3. **과목별로 구체적인 탐구 주제 2개**를 목표 학과와 성취기준에 맞춰 생성하고,
4. 생성된 탐구 주제들이 어떤 **심화 계보**로 연결되는지 **매트릭스로 시각화**합니다.

핵심 가치는 "학생부에 실제로 등장한 근거"에 기반한 **환각 없는 맞춤형 설계**와,
학교 수준·학생 부담을 반영한 **탐구 난이도 자동 조정**입니다.

### 주요 사용자
- **1차 사용자**: 학종/입시 컨설턴트 (현재 비밀번호로 접근 제한)
- 학생 본인이 직접 쓰는 시나리오도 존재하나, 현재 UI/문구는 컨설턴트 기준

## 5. 사용자 플로우 (5단계)

상단 스텝 인디케이터 기준 (앞 단계로만 자유 이동 가능):

| STEP | 이름 | 하는 일 | 관련 함수/상태 |
|------|------|---------|----------------|
| **01** | 학생 정보 + 과목 | 목표 학과(캐스케이드 선택), 학년, 이번 학기 이수 과목 선택 | `MajorCascadePicker`, `SubjectCascadePicker`, `studentInfo`, `selectedSubjects` |
| **02** | 학생부 + 학교 환경 | 학생부 PDF 업로드(텍스트/이미지 자동 판별) + 학교 창체 환경(자율/동아리/진로/학교계획) 자료 + (1학년은 관심사) + 탐구 난이도 선택 | `handlePdf...`, `schoolContext`, `freshmanInterest`, `schoolGoal`, `studentBurden` |
| **03** | 프로파일 + 총론 | AI가 **프로파일(진단)** + **설계 방향 총론**을 한 번에 생성. 학생부 평균 Level 추정 | `generateOverview()` |
| **04** | 진로 구체화 | 3가지 질문(폼) → AI가 **진로 정체성 한 줄** 도출 → 자연어로 수정 가능. 건너뛰기 가능 | `submitFormAndFinalize()`, `finalizeIdentity()`, `reviseIdentity()`, `skipInterview()` |
| **05** | 교과별 컨셉 + 내보내기 | 과목별 **탐구 주제 ①②** 생성(4개씩 청크 병렬) → **계보 매트릭스** 자동 시각화 → 결과 확인/재생성/빈 계보 채우기 | `generateSubjects()`, `regenerateSubject()`, `fillGenealogy()`, `GenealogyMatrix` |

**접근 게이트 (렌더 전 2단계 검사)**
1. 🔒 비밀번호 인증 (`isAuthenticated`) — 통과 못 하면 잠금 화면
2. 📁 데이터 로드 (`curriculumData`, `customMajorDB`) — 없으면 업로드 화면
3. 🏁 둘 다 통과 시 메인 대시보드

## 6. 핵심 도메인 개념 (개발자용 용어 정리)

| 용어 | 의미 |
|------|------|
| **학종 / 학생부종합전형** | 내신·비교과·세특 등 학생부 전반을 정성 평가하는 대입 전형 |
| **학생부** | 학교생활기록부. 학년별 수상·자율/동아리/진로 활동·교과 세특·행동특성 포함 |
| **세특(세부능력 및 특기사항)** | 과목별로 교사가 기록하는 탐구/수행 내용. 이 앱의 최종 설계 대상 |
| **총론 / 각론** | 총론 = 전체 설계 방향(STEP3), 각론 = 과목별 구체 탐구 주제(STEP5) |
| **심화 계보** | 학년을 넘나들며 하나의 주제가 심화되는 탐구의 "줄기". 시각화 핵심 축 |
| **탐구 Level (1~4)** | 탐구 난이도. 1=교과 충실 ~ 4=학과 심화(논문 수준). 자동 계산(7장) |
| **진로 정체성** | 입학사정관이 한 문장으로 학생을 파악하게 하는 진로 선언문(STEP4) |
| **계열 매핑** | 학과명 → 9개 큰 계열 자동 분류 → 진로 연계 과목 힌트 제공 |

## 7. 탐구 난이도(Level) 시스템

세특 탐구의 깊이를 **학생부 근거 우선**으로 자동 결정하는 로직.

**입력**
- `schoolTier`: 목표 학과명 → 학교 수준 자동 분류 (`classifySchoolTier`). 내부 변수(UI 미노출)
  - 최상위(서울대/KAIST/POSTECH/의·치·약·한의) / 상위 / 중상위 / 중위 / 그 외
- `schoolGoal`: "도전" | "안정" | "적정" (사용자 선택)
- `studentBurden`: "가볍게" | "보통" | "도전적으로" (사용자 선택)
- `baseLevel`: **AI가 학생부를 분석해 추정한 학생 평균 활동 Level (1~4)**
  - 총론 결과 첫 줄 `[학생부 평균 활동 Level: N]` 패턴을 정규식으로 파싱

**계산** (`calculateFinalLevel`)
```
tierBase = {최상위:4, 상위:3, 중상위:2, 중위:2, 그외:1}
level = tierBase[tier] + goalAdj{도전:+1,안정:0,적정:-1} + burdenAdj{가볍게:-1,보통:0,도전적으로:+1}
level = clamp(level, 1, 4)
finalLevel = max(baseLevel, userLevel)   // ★ 학생부 우선 원칙(높은 쪽)
```

**진정성 경고**: `|finalLevel - baseLevel| >= 2 && finalLevel > baseLevel` → 결과물에 경고 표시.
(학생 실제 수준보다 과도하게 높은 난이도로 조작할 위험 방지)

**Level 정의** (`DIFFICULTY_LEVELS`)

| Lv | 이름 | 설명 |
|----|------|------|
| 1 | 교과 충실 | 단원 성취기준 안 개념만. 문헌 정리·진로 인터뷰 중심 |
| 2 | 교과 확장 | 단원 + 인접 개념. 비교분석·케이스스터디·소규모 설문 |
| 3 | 학과 입문 | 대학 1~2학년 교재 수준. 실험 설계·데이터 수집·통계 |
| 4 | 학과 심화 | 학술 논문 수준. 모델링·시뮬레이션·메타분석 |

## 8. 데이터 모델

### 8.1 `curriculum.json` — 교과 성취기준 DB (public, 자동 fetch)

과목명별 인덱싱 구조. 앱 시작 시 `fetch('/curriculum.json')`으로 로드하며,
창의적 체험활동 3종(자율/동아리/진로활동)을 없으면 자동 주입.

```jsonc
{
  "미적분": {
    "교과군": "수학",
    "과목분류": "일반선택",
    "standards": [
      {
        "코드": "수학코드",
        "단원": "단원명",
        "성취기준": "성취기준 원문",
        "기본키워드": "교과서 개념",
        "융합키워드": "전공 연계 예시(형식 참고용)"
      }
    ]
  },
  "자율활동":   { "교과군": "창의적 체험활동", "과목분류": "창체", "standards": [] },
  "동아리활동": { ... }, "진로활동": { ... }
}
```
> CSV 업로드 경로(`handleCurriculumUpload`)도 존재. 필수 컬럼: `과목명, 단원명, 성취기준`
> (+`과목코드, 교과(군), 과목분류, 기본_키워드(교과서 개념), 융합_키워드(전공 연계)`). BOM 처리 포함.

### 8.2 `majors.json` — 학과 DB (public, 자동 fetch)

`"대학교 모집단위명"` 키 구조. CSV 업로드 경로(`handleMajorDBUpload`)도 존재.
- CSV 필수 컬럼: `대학교, 모집단위명` (+`광역, 기초, 계열`)
- 중복 제거 기준: `대학교__모집단위명`
- 학과 상세 필드(keywords/research_areas/인재상/추천_탐구방향/주의사항)는 **비어 있을 수 있으며**,
  AI 자동 생성(`generateMajorInfo`) 또는 컨설턴트가 직접 보강 → 검수 캐시에 저장

### 8.3 내장 상수 (코드에 하드코딩, `sebak_designer_v55.jsx`)

| 상수 | 역할 |
|------|------|
| `MAJOR_DB` | 대표 학과 시드 정보(키워드/연구영역/인재상/추천탐구/주의사항). 3순위 fallback |

### 8.4 학과 정보 조회 우선순위 (`resolveMajorInfo`)

### 9.2 시스템 프롬프트 목록 (모두 코드 내 문자열 상수)

| 상수 | 용도 | 모델 | 출력 형식 |

| `SYSTEM_SUBJECT` / `_FRESHMAN` | 과목별 탐구 주제 ①② 생성 | MAIN | Markdown (`**[탐구 주제 ①]**` 구조) |
| `SYSTEM_INTERVIEW_CAREER_EXAMPLES` | 학과 → 진로 예시 3~4개 | FAST | JSON 배열 |
| `SYSTEM_INTERVIEW_DYNAMIC_QUESTION` | 후속 질문 동적 생성 | MAIN | 텍스트 |
| `SYSTEM_INTERVIEW_FINAL` | 답변 3개 → 진로 정체성 한 줄 | MAIN | 텍스트 |
| `SYSTEM_INTERVIEW_REVISE` | 정체성 자연어 수정 | MAIN | JSON(`status: ok/rejected`) |
| `SYSTEM_MAJOR_INFO` | 학과 상세 정보 자동 생성 | MAIN | JSON |
| `SYSTEM_GENEALOGY_MAPPING` | 계보 × 탐구주제 매핑 | FAST | JSON(`mappings`) |
| `SYSTEM_GENEALOGY_SUBJECT_PICK` | 빈 계보 채울 과목 자동 선택 | FAST | JSON |

> 공통 프롬프트 원칙: **학생부 실제 근거 인용 강제 · 추측/일반론 금지 · 환각 금지**.
> `INTERVIEW_GENERALIZATION_GUARD`는 진로 정체성이 AI 합성어/신산업 용어로 튀지 않도록
> "일반 직업명" 수준을 강제하는 공통 가드 블록.

### 9.3 총론 생성 흐름 (`generateOverview`, STEP3)
```
입력 조립: 학생정보 + 목표학과 검수정보 + 계열 힌트 + 난이도 컨텍스트 + 학생부(텍스트 or 이미지) + 학교환경 + (1학년 관심사)
   ↓ callClaude(SYSTEM_OVERVIEW[_FRESHMAN], ..., maxTokens 8000, MODEL_MAIN, images)
결과 파싱:
   - [학생부 평균 활동 Level: N] 정규식 → baseLevel
   - finalLevel = max(baseLevel, userLevel), 진정성 경고 계산
   - "===== SECTION_SPLIT =====" 기준 profileContent / designContent 분리
```

### 9.4 각론(교과별) 생성 흐름 (`generateSubjects`, STEP5)
```
과목 목록을 CHUNK_SIZE=4 단위로 분할, 청크 간 500ms 지연
각 청크: Promise.allSettled로 병렬 호출 (과목당 callClaude, maxTokens 4500, MODEL_MAIN)
   - 창의적 체험활동(자율/동아리/진로)은 성취기준 코드 없이 자유 설계 블록
   - 일반 과목은 curriculum.json 성취기준 범위 안에서만 단원 매핑 + 학생 맞춤 융합키워드 생성
   - 진로 정체성/난이도 섹션을 프롬프트에 주입
실패 과목은 개별 에러 메시지로 대체(전체 중단 없음)
완료 후 → mapTopicsToGenealogies로 계보 매핑 자동 실행
```
- `regenerateSubject(subject)`: 다른 각도로 단일 과목 재생성 + 계보 재매핑
- `fillGenealogy(g)`: 빈 계보를 채우도록, AI가 과목 자동 선택 → 기존 주제 1개 유지 + 1개를 목표 계보로 교체

### 9.5 재시도 로직 (`callClaude`)
- 5xx / 네트워크 오류 시 **최대 5회 재시도**, 백오프 **5s → 15s → 30s → 60s**
- `onRetry` 콜백으로 생성 로그에 진행 표시
- 엔드포인트는 **하드코딩**: `https://roadmapserver.onrender.com/api/chat` (14장, 환경변수화 필요)

## 10. 백엔드 API 명세 (`roadmapserver`)

### `POST /api/chat`
프론트가 보낸 프롬프트를 Anthropic으로 프록시하고 텍스트만 반환.

**Request Body (JSON, 최대 50mb)**
```jsonc
{
  "systemPrompt": "string",        // system
  "userPrompt": "string",          // user 메시지 텍스트
  "maxTokens": 4096,               // 선택, 기본 4096
  "model": "claude-sonnet-4-6",    // 선택, 기본 "claude-sonnet-4-20250514"
  "images": [                      // 선택 — 이미지 PDF 처리용
    { "base64": "...", "mediaType": "image/png" }
  ]
}
```
- `images`가 있으면 `image` 블록 배열 + 텍스트를 하나의 user 메시지로 구성
- 없으면 텍스트만 user 메시지로 전송

**Response**
```jsonc
{ "text": "생성된 텍스트(모든 text 블록 join)" }   // 200
{ "error": "메시지" }                              // 500
```

**환경변수**: `ANTHROPIC_API_KEY` (필수), `PORT` (기본 5000)
**미들웨어**: `cors()` 전체 허용, `express.json({ limit: '50mb' })`

> ⚠️ 인증/레이트리밋/오리진 제한/입력 검증 **전무**. 공개 URL로 누구나 호출 가능 → 12장.

## 12. 계보 시각화

**목적**: 총론의 "심화 계보"와 각 과목의 "탐구 주제"가 어떻게 연결되는지 매트릭스(계보 × 학년/과목)로 표현.

**파이프라인** (`mapTopicsToGenealogies`)
1. `parseGenealogiesFromOverview(overview)` — 총론 텍스트의 `## 심화 계보` 섹션에서 계보명·요약·활동을 **정규식 파싱**
2. `parseTopicsFromSubject(result, subject)` — 각 과목 결과에서 `**[탐구 주제 ①/②]**` 주제명 정규식 파싱
3. Haiku 호출(`SYSTEM_GENEALOGY_MAPPING`)로 계보 ↔ 탐구주제 매핑 JSON 생성
4. `GenealogyMatrix` 컴포넌트가 계보 행 × 연도 열 매트릭스로 렌더

> ⚠️ **정규식이 AI 출력 형식(마크다운 헤더·기호·이모지)에 강하게 결합**되어 있음.
> 프롬프트 출력 형식이 조금만 바뀌어도 파싱이 깨짐 → 취약점. 구조화 출력(툴/JSON) 전환 권장(14장).

## 13. 캐싱 / 스토리지

`window.storage` (Claude Artifact 환경 제공 API)를 통한 캐시. 헬퍼: `storageGet/Set/Delete`.

| 키 (`STORAGE_KEYS`) | 내용 | shared |
|------|------|--------|
| `hakzzong:curriculum:v1` | 교육과정 성취기준(CSV 업로드분) | ✔ |
| `hakzzong:majors:v1` | 학과 DB(CSV 업로드분) | ✔ |
| `hakzzong:major-info:v1` | AI 생성 + 검수 학과 정보 | ✔ |

> 🔴 **중대 이슈**: `window.storage`는 **Claude Artifact 런타임 전용 API**입니다.
> 일반 웹 배포 환경(Vite 정적 호스팅)에는 존재하지 않아 모든 `storageGet/Set`이 무력화됩니다
> (헬퍼가 `try/catch`로 조용히 실패). 현재는 `public/*.json` 자동 fetch로 데이터를 채우므로
> 앱은 동작하지만, **AI 검수 학과 정보 캐시는 저장되지 않고 세션마다 사라집니다.**
> → localStorage/IndexedDB 또는 서버 DB로 교체 필요(14장).

   `import.meta.env.VITE_API_BASE` 등 환경변수화 필요(개발/스테이징/운영 분리)

   모듈 분리(`/data`, `/prompts`, `/lib`, `/components`, `/hooks`) 강력 권장. 미사용 백업 파일 2개 삭제

5. **🟠 런타임 CDN 의존** — pdf.js·PapaParse를 `<script>`로 동적 로드. CSP/오프라인/CDN 장애에 취약.
   npm 의존성으로 번들링 권장

6. **🟠 AI 출력 파싱 취약성** — 계보/Level/섹션 분리를 정규식·구분자 문자열에 의존.
   프롬프트 문구 변경에 쉽게 깨짐. 구조화 출력(JSON/Tool use)로 전환 권장

7. **🟡 모델 문자열 불일치** — 프론트 기본 `claude-sonnet-4-6` vs 백엔드 기본 `claude-sonnet-4-20250514`.
   모델 상수를 한 곳에서 관리(설정/환경변수). 최신 권장 모델로 재검토

8. **🟡 비용/성능** — 학생 1명당 여러 번의 Sonnet 호출(총론 8k + 과목 N×4.5k + 매핑). 이미지 PDF는 페이지당 이미지 전송.
   토큰 사용량 모니터링·캐싱·모델 티어 최적화 필요

9. **🟡 테스트/CI 전무** — 프론트·백엔드 모두 테스트 없음(`"test": exit 1`). 최소 유닛/스모크 테스트 및 CI 파이프라인 필요

10. **🟡 관측성 부재** — 백엔드 로깅 `console.error` 수준. 에러 추적/APM/사용량 대시보드 필요
